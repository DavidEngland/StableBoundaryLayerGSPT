Here is a concrete architectural plan to implement a **Single Source of Truth (SSOT) for the List of Symbols** across the repository.

By storing all mathematical notation, code mappings, units, and definitions in a single YAML spec file, you can automatically generate the LaTeX manuscript table, Markdown documentation, and Julia context dictionaries—completely eliminating notation drift.

### Phase 2: Create Generator Script (`scripts/generate_symbols.jl`)

Build a dedicated Julia script that parses `spec/symbols.yaml` using `YAML.jl` and emits both LaTeX and Markdown artifacts.

#### Outputs Generated:

1. **`reports/generated/sections/list_of_symbols.tex`**: A publication-ready LaTeX table formatted using `longtable` or `booktabs`.
2. **`docs/SYMBOLS.md`** (or auto-updates `docs/GLOSSARY.md`): Human-readable Markdown reference table for GitHub/developers.

#### Generator Logic Sketch:

```julia
# scripts/generate_symbols.jl
using YAML

function generate_latex_table(spec::Dict)
    io = IOBuffer()
    println(io, "\\begin{table}[htbp]")
    println(io, "\\centering")
    println(io, "\\caption{List of symbols, mathematical definitions, physical units, and model variable bindings.}")
    println(io, "\\label{tab:list_of_symbols}")
    println(io, "\\small")
    println(io, "\\begin{tabular}{llll}")
    println(io, "\\toprule")
    println(io, "Symbol & Description & Units & Code Mapping \\\\")
    println(io, "\\midrule")

    for cat in spec["categories"]
        cat_symbols = filter(s -> s["category"] == cat["id"], spec["symbols"])
        if !isempty(cat_symbols)
            println(io, "\\multicolumn{4}{l}{\\textbf{$(cat["name"])}} \\\\")
            println(io, "\\midrule")
            for s in cat_symbols
                sym = "\\(\$(s["symbol_tex"])\\)"
                desc = s["description"]
                units = s["units_tex"] == "-" ? "---" : "\\(\$(s["units_tex"])\\)"
                code = "\\texttt{\$(s["code_key"])}"
                println(io, "\$sym & \$desc & \$units & \$code \\\\")
            end
            println(io, "\\midrule")
        end
    end

    println(io, "\\bottomrule")
    println(io, "\\end{tabular}")
    println(io, "\\end{table}")
    return String(take!(io))
end

```

### Phase 3: Integrate into Manuscript Assembly Pipeline

Wire the SSOT directly into `scripts/assemble_manuscript.jl` and your `Makefile`:

1. **Pre-assembly Build Step:**
Add `julia scripts/generate_symbols.jl` as a prerequisite before assembling templates.
2. **Automated Mustache Context Mapping:**
Inside `assemble_manuscript.jl`, automatically populate symbol Mustache macros directly from `spec/symbols.yaml`:
```julia
symbols_spec = YAML.load_file("spec/symbols.yaml")
for s in symbols_spec["symbols"]
    # Automatically creates mustache context keys like "symbol_beta_t_tex" => "\beta_T"
    context["symbol_$(s["id"])_tex"] = "\\($(s["symbol_tex"])\\)"
end

```


3. **Template Inclusion:**
Include the generated LaTeX table via a Mustache tag or standard LaTeX input inside `templates/sections/`:
```latex
\input{reports/generated/sections/list_of_symbols.tex}

```

### Phase 4: Automated Verification & Drift Audit

To ensure developers do not introduce new parameters without registering them in the SSOT, add a CI unit test (`test/test_symbols_ssot.jl`):

* **Check 1:** Verify every parameter in `spec/datasets/CASES99.yaml` exists in `spec/symbols.yaml`.
* **Check 2:** Verify every Mustache parameter macro (`param_*_code` / `param_*_tex`) in `templates/sections/*.tex.mustache` has a corresponding entry in `spec/symbols.yaml`.
* **Check 3:** Fail CI build if an unregistered variable or parameter is detected.

### Benefits

* **Zero Notation Drift:** Updating $\beta_T$ or $\alpha_{\mathrm{safe}}$ in `spec/symbols.yaml` instantly updates the paper's symbol table, documentation, and template macros.
* **Reviewer Transparency:** Provides an exact, auto-generated cross-reference table mapping manuscript math symbols directly to Julia variable keys (`x[1]`, `x[4]`, `alpha_safe`).
* **Clean Codebase Separation:** Parameter metadata stays isolated from core ODE solver logic in `Dynamics.jl`.
